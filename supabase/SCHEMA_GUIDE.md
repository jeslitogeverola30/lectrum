# Lectrum Supabase Schema Guide

## Overview
This document explains the complete SQL schema for the Lectrum app - a quiz battle platform where users can study in groups, create quizzes, and compete in real-time battles.

---

## Database Tables

### 1. **profiles** - User Profiles
Extends Supabase `auth.users` table.
```
- id (UUID) - Primary key, references auth.users
- username - Unique username
- email - User email
- avatar_emoji - Display emoji (default: 👤)
- avatar_url - URL to profile image
- bio - User biography
- elo_rating - Current ELO rating (default: 1200)
- total_matches - Total battles played
- wins - Total wins
- losses - Total losses
- created_at - Account creation timestamp
- updated_at - Last profile update
```

### 2. **quizzes** - Quiz Content
Stores quiz questions generated by Gemini API.
```
- id (UUID) - Primary key
- creator_id (UUID) - References profiles.id
- topic - Quiz topic/subject
- description - Quiz description
- raw_json_content (JSONB) - Quiz questions JSON from Gemini
- question_count - Number of questions
- is_public - Public visibility flag
- created_at - Quiz creation timestamp
- updated_at - Last update timestamp
```

**JSON Structure Example:**
```json
[
  {
    "question": "What is the capital of France?",
    "options": ["London", "Paris", "Berlin", "Madrid"],
    "answerIndex": 1,
    "explanation": "Paris is the capital and largest city of France."
  }
]
```

### 3. **rooms** - Study Groups
Virtual study rooms where users chat and battle.
```
- id (UUID) - Primary key
- creator_id (UUID) - Room creator, references profiles.id
- name - Room name
- topic - Study topic
- avatar_emoji - Room emoji icon
- description - Room description
- member_limit - Max members (default: 10)
- is_private - Private/public flag
- room_code - 5-digit unique code for joining
- created_at - Room creation timestamp
- updated_at - Last update timestamp
```

### 4. **room_members** - Room Membership
Junction table for users in rooms.
```
- id (UUID) - Primary key
- room_id (UUID) - References rooms.id
- user_id (UUID) - References profiles.id
- role - Member role: 'creator', 'admin', 'member'
- joined_at - Join timestamp
```

### 5. **messages** - Room Chat
Messages in study rooms.
```
- id (UUID) - Primary key
- room_id (UUID) - References rooms.id
- sender_id (UUID) - Message sender, references profiles.id
- text - Message content (max 500 chars in app)
- attachment_url - URL to attachments (files, images)
- created_at - Message timestamp
- updated_at - Last edit timestamp
```

### 6. **battles** - Quiz Battles
Container for competitive quiz sessions.
```
- id (UUID) - Primary key
- room_id (UUID) - Associated room (optional)
- quiz_id (UUID) - Quiz being used (optional)
- creator_id (UUID) - Battle organizer, references profiles.id
- round_count - Number of questions (1-10)
- status - 'pending' | 'active' | 'completed'
- winner_id (UUID) - Battle winner (optional for ties)
- created_at - Battle created timestamp
- started_at - Battle start timestamp
- ended_at - Battle end timestamp
- updated_at - Last update timestamp
```

### 7. **battle_participants** - Battle Players
Tracks users and their scores in battles.
```
- id (UUID) - Primary key
- battle_id (UUID) - References battles.id
- user_id (UUID) - References profiles.id
- score - Total points scored
- correct_answers - Number of correct answers
- total_answers - Total questions answered
- streak - Current correct answer streak
- joined_at - Join timestamp
```

### 8. **match_history** - Historical Results
Records all historical battle results.
```
- id (UUID) - Primary key
- battle_id (UUID) - References battles.id
- player_1_id (UUID) - First player, references profiles.id
- player_2_id (UUID) - Second player, references profiles.id
- winner_id (UUID) - Winner (optional for ties)
- player_1_score - Player 1's final score
- player_2_score - Player 2's final score
- elo_change_p1 - ELO rating change for player 1
- elo_change_p2 - ELO rating change for player 2
- created_at - Match completion timestamp
```

## Key Views

### **active_battles**
Shows all ongoing and pending battles with participant count.

### **room_activity**
Aggregates room statistics: members, messages, last activity.

### **leaderboard**
Ranked user list by ELO rating with win rates.

## Row Level Security (RLS)

All tables have RLS enabled with specific policies:

| Table | Policy | Access |
|-------|--------|--------|
| profiles | Public view, self-update | All users can view; users can update own |
| quizzes | Public if `is_public=true` | Creators can manage; public quizzes visible |
| rooms | Based on privacy & membership | Private rooms: members only; public: all |
| room_members | View all | Anyone can view membership |
| messages | Members only | Room members can read/write |
| battles | Participants only | Creators and participants can view |
| match_history | Public view | All users can view |

## Common Queries

### Get a user's leaderboard position
```sql
SELECT 
  username, 
  elo_rating, 
  win_rate,
  ROW_NUMBER() OVER (ORDER BY elo_rating DESC) as rank
FROM leaderboard
ORDER BY elo_rating DESC;
```

### Get room messages with usernames
```sql
SELECT 
  m.text,
  p.username,
  p.avatar_emoji,
  m.created_at
FROM messages m
JOIN profiles p ON m.sender_id = p.id
WHERE m.room_id = $1
ORDER BY m.created_at DESC;
```

### Get user's recent battles
```sql
SELECT 
  b.id,
  b.room_id,
  b.status,
  bp.score,
  bp.correct_answers,
  bp.total_answers,
  b.created_at
FROM battles b
JOIN battle_participants bp ON b.id = bp.battle_id
WHERE bp.user_id = $1
ORDER BY b.created_at DESC
LIMIT 10;
```

### Update user ELO after battle (for your backend)
```sql
UPDATE profiles
SET 
  elo_rating = elo_rating + $1,
  total_matches = total_matches + 1,
  wins = CASE WHEN $2 = true THEN wins + 1 ELSE wins END,
  losses = CASE WHEN $2 = false THEN losses + 1 ELSE losses END
WHERE id = $3;
```

## Integration Notes

### From Your App Code:

1. **Create Quiz** - Saves to `quizzes` table via `create_quiz.jsx`
2. **Join Room** - Inserts into `room_members` table
3. **Send Message** - Inserts into `messages` table
4. **Start Battle** - Creates `battles` + `battle_participants` entries
5. **Record Results** - Inserts into `match_history`, updates `profiles` ELO

### Environment Variables Needed:
```
EXPO_PUBLIC_SUPABASE_URL=your-project.supabase.co
EXPO_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
GEMINI_API_KEY=your-gemini-key (for generate-quiz edge function)
```

## Troubleshooting

**"Permission denied" errors:**
- Ensure user is authenticated in Supabase Auth
- Check RLS policies match your use case
- Verify `auth.uid()` is returning the correct UUID

**"Foreign key constraint violation":**
- Ensure parent records exist before inserting
- Check cascade delete policies

**Slow queries:**
- Review query plans in Supabase dashboard
- Verify indexes are being used
- Consider materializing views for complex aggregations
